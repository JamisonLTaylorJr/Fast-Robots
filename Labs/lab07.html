Lab 7: Kalman Filter

In this lab, I implemented a Kalman Filter to improve the robot’s state estimation and allow for faster and smoother motion toward the wall. Instead of relying only on slow Time-of-Flight (ToF) updates, the Kalman Filter combines a system model with sensor data to estimate both position and velocity in real time.

1. Objective

The goal of this lab was to use a Kalman Filter to supplement noisy and slow ToF measurements, allowing the robot to move faster while still accurately stopping at a desired distance. This builds directly on Lab 5 by replacing linear extrapolation with a model-based estimation approach.

2. Step Response + Data Collection

I collected step response data by driving the robot toward a wall at a constant PWM input. Using my Bluetooth debugging framework, I logged ToF distance, PWM input, and time values over a fixed number of iterations.

The robot was run long enough to reach steady state, and foam was used to prevent damage when approaching the wall. Data was sent back to Jupyter after the run for analysis.

3. Velocity + Rise Time Estimation

Velocity was computed by taking the numerical derivative of the ToF distance data. To reduce noise, smoothing was applied before computing acceleration and other derived quantities.

From the velocity curve, I extracted key system characteristics:

  • Rise time (to ~90%): 0.868 s
  • Sampling behavior: 13 data points over 1.229 s
  • Approximate loop rate: ~10.6 loops/sec

I also plotted the 90% velocity line and identified the corresponding time index directly in Python to help estimate system parameters.

4. System Modeling

Using the step response data, I estimated the system dynamics needed to construct the state-space model. The system was modeled with two states:

  • Position (distance to wall)
  • Velocity

The A and B matrices were derived based on the observed rise time and steady-state behavior. These matrices were then discretized using the sampling time of the system. 

Ad = I + dt * A
Bd = dt * B

The measurement matrix C was defined to reflect that only distance was directly measured: 

C = [-1  0]

5. Kalman Filter (Python Implementation)

I first implemented the Kalman Filter in Jupyter to validate the model before deploying it on the robot. The filter combines prediction (model-based) and correction (sensor-based) steps. 

def kf(mu, sigma, u, y):
    mu_p = A.dot(mu) + B.dot(u)
    sigma_p = A.dot(sigma.dot(A.transpose())) + Sigma_u

    sigma_m = C.dot(sigma_p.dot(C.transpose())) + Sigma_z
    K = sigma_p.dot(C.transpose().dot(np.linalg.inv(sigma_m)))

    mu = mu_p + K.dot(y - C.dot(mu_p))
    sigma = (np.eye(2) - K.dot(C)).dot(sigma_p)

    return mu, sigma

I tuned the process noise (Q) and measurement noise (R) matrices to balance responsiveness and noise rejection. Larger process noise made the filter respond faster, while larger measurement noise made it rely more on the model.

6. On-Robot Implementation

After verifying the Kalman Filter in Python, I implemented it directly on the Artemis using matrix operations. The filter runs inside the control loop and provides continuous estimates of position and velocity.

This replaced the linear extrapolation approach used in Lab 5 and allowed the robot to react more smoothly between ToF updates.

7. Discussion

The Kalman Filter significantly improved performance by reducing noise and providing better estimates of velocity. This allowed the robot to move faster while still stopping accurately.

One of the most important parts of this lab was tuning the covariance matrices. If the process noise was too low, the filter became too slow. If it was too high, the estimates became unstable.

Overall, the Kalman Filter provided a much more robust solution compared to relying solely on raw sensor data or simple extrapolation.
